# Бронирование переговорной

Тестовое задание Frontend Engineer: интерфейс бронирования переговорной комнаты в течение рабочего дня (09:00–18:00).

- Демо: _[https://reservation-app-pi-ten.vercel.app/](https://reservation-app-pi-ten.vercel.app/)_
- Затраченное время: _3 часа_

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

| Скрипт | Назначение |
|---|---|
| `npm run dev` | dev-сервер Vite |
| `npm run build` | проверка типов + production-сборка |
| `npm run preview` | просмотр production-сборки |
| `npm test` | unit-тесты бизнес-правил (Vitest) |
| `npm run lint` | линтер (oxlint) |
| `npm run typecheck` | только проверка типов |

## Стек

- React 19, TypeScript, Vite
- TanStack Query — серверное состояние (загрузка, кеш, мутации, инвалидация)
- React Router — выбранная дата хранится в URL
- MSW — mock API на уровне сети
- Vitest — тесты валидации
- Чистый CSS без UI-библиотек

## Структура


### Разделение слоёв

- **UI** (`components/`) не знает про `fetch` и URL — работает только через хуки из `hooks/`.
- **Хуки** вызывают `api/bookings.ts`; после любой мутации (успешной или с ошибкой, включая 409) инвалидируют кеш броней, и список перезапрашивается.
- **Сетевой слой** (`api/`) — обычный `fetch` на `/api/...`. Базовый URL берётся из `VITE_API_URL` (по умолчанию `/api`). Чтобы подключить реальный бэкенд, достаточно указать `VITE_API_URL` и не запускать MSW в `main.tsx` — UI и хуки не меняются.
- **Бизнес-правила** (`lib/validation.ts`) — чистые функции без зависимостей от React. Их вызывают и форма (мгновенная обратная связь), и mock-сервер (источник истины), поэтому правила описаны в одном месте.

## Уточнения ТЗ и принятые решения

Вопросы были заданы заказчику до начала работы:

| Вопрос | Ответ / решение |
|---|---|
| Часовой пояс для «сегодня» и «прошедшего времени» | Время браузера пользователя |
| Шаг времени | 15 минут. Время выбирается из списков с шагом 15 минут; сервер отклоняет время вне сетки |
| Бронь, заканчивающаяся в 18:00 | 17:00–18:00 допустима, 17:30–18:30 — нет |
| Редактирование/удаление начавшихся и прошедших броней | Трактовка правила 6: начавшиеся и завершённые брони — только для чтения (нельзя изменить или удалить). Проверяется и в UI, и на сервере |
| Формат ошибок API | `{ code, message, details? }` со статусами 400 / 404 / 409 |
| Имитация конфликта (правило 8) | Переключатель в dev-панели — на усмотрение исполнителя |

Дополнительно:

- Начать бронь «прямо сейчас» нельзя: для сегодняшней даты старт должен быть строго позже текущей минуты, т.е. ближайший доступный слот — следующий по сетке. Та же граница определяет, что бронь «началась» и заблокирована.
- Касание границ не считается пересечением: интервалы полуоткрытые `[start, end)`.
- Название брони необязательное (до 100 символов).

## Бизнес-правила

Все проверки — в `validateBooking()` (`lib/validation.ts`). Порядок: блокировка → формат → сетка → рабочий день → start < end и длительность → прошедшее время → пересечения.

| Правило ТЗ | Код ошибки | Как реализовано |
|---|---|---|
| 1. В пределах рабочего дня | `OUT_OF_WORK_HOURS` | старт в `[09:00, 18:00)`, окончание в `(09:00, 18:00]` |
| 2. start < end | `START_NOT_BEFORE_END` | |
| 3. Минимум 30 минут | `TOO_SHORT` | |
| 4. Максимум 2 часа | `TOO_LONG` | |
| 5. Без пересечений, касание допустимо | `OVERLAP` | `aStart < bEnd && bStart < aEnd` |
| 6. Нельзя в прошлое | `PAST_DATE`, `PAST_TIME` | прошедшая дата — создание недоступно; сегодня — прошедшие слоты недоступны |
| 6. Начавшиеся брони | `LOCKED` | при PATCH/DELETE сервер проверяет исходную бронь |
| 7. Бронь не конфликтует сама с собой | — | при редактировании исходная бронь исключается из проверки пересечений |
| Сетка 15 минут | `OFF_GRID` | |
| Корректный формат | `INVALID_FORMAT` | `HH:mm`, `YYYY-MM-DD` и существование даты (`2026-13-45` отклоняется) |

Хелперы для формы:

- `isStartAvailable()` — старт доступен, если он не в прошлом и от него помещается хотя бы бронь минимальной длительности (поэтому 17:45 и слот вплотную перед чужой бронью недоступны).
- `getEndOptions()` — варианты окончания: от `start + 30 мин` до ближайшего из `start + 2 ч`, `18:00` и начала следующей брони.

## API (mock)

Реализован на MSW (`mocks/handlers.ts`), задержка ответа 300–600 мс. Данные хранятся в памяти и сбрасываются при перезагрузке страницы; на сегодня создаются две стартовые брони. MSW включён и в production-сборке — на нём работает демо.

| Метод | Путь | Ответы |
|---|---|---|
| GET | `/api/bookings?date=YYYY-MM-DD` | 200 `Booking[]` (по возрастанию start), 400 без даты |
| POST | `/api/bookings` | 201 `Booking`, 400, 409 |
| PATCH | `/api/bookings/:id` | 200 `Booking`, 400 (в т.ч. начавшаяся бронь), 404, 409 |
| DELETE | `/api/bookings/:id` | 204, 400 (начавшаяся бронь), 404 |

```ts
type Booking = {
  id: string;
  date: string;   // YYYY-MM-DD
  start: string;  // HH:mm
  end: string;    // HH:mm
  title?: string;
};

type ApiErrorBody = {
  code: 'VALIDATION' | 'CONFLICT' | 'NOT_FOUND' | 'UNKNOWN';
  message: string;
  details?: unknown; // 400: { errors: ValidationError[] }, 409: { conflicts: Booking[] }
};
```

- Пересечение → **409** `CONFLICT`, остальные нарушения правил → **400** `VALIDATION` (`message` — первое нарушение, полный список в `details.errors`).
- PATCH принимает частичное тело и накладывает его на исходную бронь, после чего проверяет результат целиком.

### Имитация гонки (правило 8)

Внизу страницы есть dev-панель с переключателем **«Имитировать гонку»**. Пока он включён, каждое сохранение (POST/PATCH), прошедшее валидацию, «перехватывается»: мок вставляет на запрошенный слот бронь «Занято другим пользователем» и отвечает 409.

Как проверить: включить переключатель → выбрать свободное время → «Забронировать». Ожидаемо: сообщение о конфликте, список обновился и показывает чужую бронь, введённые в форму данные остались на месте.

При редактировании гонка не имитируется, если новое время пересекается со старым временем этой же брони — иначе в хранилище появились бы пересекающиеся записи.

## Интерфейс

**Выбор даты.** Выбранная дата хранится в URL (`?date=YYYY-MM-DD`): переживает перезагрузку, ссылкой можно поделиться, кнопки «назад/вперёд» браузера переключают даты. Некорректная или отсутствующая дата → сегодня.

**Список броней** на выбранную дату:

- состояния: загрузка, пустой список, ошибка загрузки с кнопкой «Повторить», индикатор фонового обновления;
- статус брони: «Идёт» / «Прошла»; у таких броней нет кнопок изменения и удаления;
- удаление с подтверждением, кнопка блокируется на время запроса, ошибка удаления показывается над списком;
- редактируемая бронь подсвечивается.

**Форма** (создание и редактирование):

- время начала и окончания выбирается из списков с шагом 15 минут; занятые, прошедшие и неподходящие варианты недоступны для выбора;
- при смене начала окончание сохраняется, если всё ещё допустимо, иначе подставляется минимальная длительность;
- ошибки валидации показываются под полями сразу при выборе времени;
- на время отправки поля и кнопка заблокированы, текст кнопки — «Сохранение…»;
- **ошибка сервера / 409:** понятное сообщение, список броней перезапрашивается, введённые данные не сбрасываются — пользователь выбирает другое время и отправляет снова;
- **смена даты** не сбрасывает черновик новой брони (время и название сохраняются, сообщения от прошлой даты убираются); если время на новой дате недоступно, это видно по ошибке валидации;
- для прошедшей даты вместо формы — сообщение «На прошедшую дату создать бронь нельзя», для полностью занятого дня — «свободного времени не осталось»;
- «Отмена» выходит из режима редактирования; смена даты во время редактирования (в т.ч. через историю браузера) тоже выходит из него.

Текущее время обновляется каждые 30 секунд (`useNow`), поэтому статусы броней и доступные слоты не устаревают, если вкладка открыта долго.

**Адаптивность:** на ширине от 768px список и форма в две колонки, на узких экранах — в одну.

**Доступность:** у полей есть `label`; невалидные поля помечены `aria-invalid` и связаны с текстом ошибки через `aria-describedby`; ошибки формы объявляются через `role="alert"` / `aria-live`; загрузка — `role="status"`, `aria-busy` у списка; у кнопок в списке — `aria-label` с временем брони; видимый `:focus-visible`.

## Тесты

`npm test` — 13 тестов на `lib/validation.ts`: касание границ, пересечение, редактирование без конфликта с собой, окончание в 18:00, граничные длительности 30 мин / 2 ч, сетка, start ≥ end, прошедшие дата и время (включая «прямо сейчас»), блокировка начавшейся брони, несуществующая дата, варианты окончания и доступность старта.

## Что не сделано / что бы доделал

- Тесты компонентов (Testing Library + MSW в Node) на сценарий с 409 и сохранение данных формы.
- Сохранение данных mock-сервера в `localStorage` — сейчас брони сбрасываются при перезагрузке.
- Управление фокусом: перевод фокуса в форму при «Изменить» и возврат в список после сохранения.
- Визуальный таймлайн дня вместо списка.
- Оптимистичные обновления — сознательно не использовал: при возможных конфликтах проще и честнее дождаться ответа сервера.
